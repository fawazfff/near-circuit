# NEAR Circuit — Learning Curriculum

The Academy is a first-class part of the game, not optional flavour text. Every module must explain a concept, let the player interact with a simplified model, make clear what happened and test understanding.

## Module map

| Module | Essential learning outcome | Playable experience |
|---|---|---|
| 01. Blockchain fundamentals | Explain a shared ledger, blocks and network verification | Submit a race result and ask several independent nodes to verify it |
| 02. NEAR Protocol | Explain NEAR, validators, proof of stake and Nightshade at a high level | Run a simplified network round showing validators and shards |
| 03. Accounts and wallets | Distinguish an account, wallet interface, public account ID and private key | Walk through a pit-stop authorisation flow |
| 04. Transactions and smart contracts | Explain a transaction, contract call, execution and gas | Trace an equipment purchase from request to result |
| 05. Tokens and NEP-245 | Explain token types, multi-token contracts and ownership | Collect and transfer distinct equipment types in a clearly labelled local demo |
| 06. NEAR ecosystem | Recognise applications, wallets, DeFi, infra, developer tools, AI and games | Explore Ecosystem City and inspect real examples and official resources |
| 07. NEAR Intents and chain abstraction | Explain a desired outcome, solvers and hiding network complexity | Compare illustrative routes to an upgrade; not a live order |
| 08. AI agents and the agent economy | Explain agents, permissions, wallet safety and observable decisions | Inspect a merchant's stock/cash and watch its rule-based decision |

## Assessment

- Each module includes one multiple-choice mastery check.
- A correct answer marks the module complete and awards Academy XP.
- Wrong answers show a short explanation and allow a retry.
- Completed modules appear in the Circuit Codex.
- Academy progress is saved locally in prototype 0.1.0.

## Teaching principles

- Assume the player knows nothing about crypto.
- Explain one idea at a time using familiar examples from racing and ownership.
- Define terms before using acronyms.
- Distinguish a blockchain, a wallet, an account, a token and an application.
- Label local simulations so they are not mistaken for real NEAR transactions.
- Link to official docs for players who want technical depth.
- Avoid presenting market prices, speculative returns or token price forecasts as learning outcomes.

## Accuracy boundaries

- The validator/shard visual is an educational simplification, not a live topology visualiser.
- The transaction lifecycle in the Academy is a guided illustration until a testnet adapter is wired.
- The multi-token locker is a local learning simulation until a deployed NEP-245 contract is connected.
- Intent route comparison is illustrative until a real supported NEAR Intents integration is implemented.
- Merchant agents use deterministic rules in the prototype. The live wallet-backed agent implementation is a future integration milestone.
